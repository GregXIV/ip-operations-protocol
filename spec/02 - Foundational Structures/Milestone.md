# Milestone

> A unit of work within a [Workstream](Workstream.md), with its own lifecycle and authority.

The protocol uses "milestone" to mean a unit of work in a chain (validation analysis, document preparation, EPO terminal action) — closer to PM-style usage than to BPMN's "intermediate event" or CMMN's "achievement marker." The work-completion event is the milestone "reaching" terminal state.

## Structure

### `milestoneUri`
Type: URI, required

Stable identifier of the form `urn:ipproto:milestone:{uuid}`. Generated by the orchestrator at [Workstream](Workstream.md) creation.

### `milestoneSequence`
Type: integer, required

Position in the chain. For DAGs, a topologically-consistent sequence number used for display ordering.

### `milestoneTitle`
Type: string, required

Short human-readable label.

### `milestoneDescription`
Type: string, optional

Longer description used in proposals.

### `milestoneCategory`
Type: URI, required

Typed classification. Standard categories grouped:

**Analysis:** `validationAnalysis`, `freedomToOperate`, `priorArtSearch`, `patentabilityAssessment`

**Document preparation:** `officeFormPreparation`, `translationPreparation`, `responseDrafting`

**Execution and filing:** `officeFiling`, `clientExecutedFiling`, `thirdPartyExecutedFiling`

**Payments:** `officeFeePayment`, `translationFeePayment`, `representationFeePayment`

**Subscriptions:** `renewalMonitoringEnrollment`, `oppositionWatchEnrollment`, `portfolioMonitoringEnrollment`

**Other:** `correspondenceHandling`, `custom`

All in `urn:ipproto:milestoneCategory:` namespace.

### `actorAssignments`
Type: array of structured entries, required (at least one)

Each entry assigns an actor to a role:
- `actorUri` — [Actor Reference](Actor%20Reference.md)
- `roleDeclarationUri` — [Actor Role Declaration](Actor%20Role%20Declaration.md)
- `assignmentType` — enumeration: `primary`, `delegatedFrom`, `accountableTo`, `payor`, `observer`

A milestone typically has multiple entries — the worker (`primary`), the corporate (`accountableTo`), the corporate again (`payor` if paying directly), optional delegation entries.

### `executionMode`
Type: enumeration, required

- `serviceProviderManaged` — performed by the contracted service provider
- `selfService` — performed by the corporate's own staff
- `thirdPartyRfp` — procured through marketplace RFP

### `serviceProviderActorUri`
Type: [Actor Reference](Actor%20Reference.md) URI, conditional

Required when `executionMode == serviceProviderManaged`. Identifies which provider is engaged.

### `dependencies`
Type: array of structured entries, optional

Other milestones that must reach a state before this one can begin. Each entry: `dependsOnMilestoneUri`, `requiredState` (`committed`, `started`, `completed`).

### `milestoneStatus`
Type: enumeration, required

- `proposed` — part of a proposed workstream, not yet authorized
- `committed` — authorized but dependencies not yet satisfied
- `notReady` — committed, dependencies not satisfied
- `ready` — dependencies satisfied; awaiting `MilestoneStarted`
- `inProgress` — work is happening
- `awaitingExternalAction` — work has produced an artifact awaiting external action (the hard-handoff state)
- `completed`
- `failed`
- `abandoned`

### `statusHistory`
Type: array, required

Append-only log of status transitions, same shape as in [Workstream](Workstream.md).

### `estimates`
Type: structured, required

- `estimatedCost` — `amount`, `currency`, optional `costBreakdown`
- `estimatedDuration` — `minimumDays`, `expectedDays`, `maximumDays`
- `estimatedAt` — ISO 8601 datetime

### `actuals`
Type: structured, optional

Populated as the milestone progresses. Same shape as `estimates` plus `varianceExplanation`.

### `deliverables`
Type: array of [Document Reference](Document%20Reference.md) URIs, optional

### `milestoneAuthorityClaims`
Type: array of [Authority Claim](Authority%20Claim.md) URIs, required

## Worked example

```json
{
  "milestoneUri": "urn:ipproto:milestone:m1-validation-analysis",
  "milestoneSequence": 1,
  "milestoneTitle": "EP validation analysis",
  "milestoneCategory": "urn:ipproto:milestoneCategory:validationAnalysis",
  "actorAssignments": [
    {
      "actorUri": "urn:ipproto:actor:meridian-ip-group",
      "roleDeclarationUri": "...",
      "assignmentType": "primary"
    },
    {
      "actorUri": "urn:ipproto:actor:northwind-industries",
      "roleDeclarationUri": "...",
      "assignmentType": "accountableTo"
    },
    {
      "actorUri": "urn:ipproto:actor:northwind-industries",
      "roleDeclarationUri": "...",
      "assignmentType": "payor"
    }
  ],
  "executionMode": "serviceProviderManaged",
  "serviceProviderActorUri": "urn:ipproto:actor:meridian-ip-group",
  "dependencies": [],
  "milestoneStatus": "ready",
  "estimates": {
    "estimatedCost": {"amount": 850, "currency": "EUR"},
    "estimatedDuration": {"minimumDays": 3, "expectedDays": 5, "maximumDays": 10}
  },
  "milestoneAuthorityClaims": ["urn:ipproto:authorityClaim:..."]
}
```
