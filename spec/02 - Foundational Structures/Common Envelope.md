# Common Envelope

> Shared structure that wraps every message in the protocol.

Every message in the protocol carries a common envelope of metadata fields outside the message-specific payload. This is defined once here rather than repeated in each message specification.

## Required fields

### `messageUri`
Type: URI

Stable identifier of the message instance, of the form `urn:ipproto:message:{uuid}`. Generated by the originating actor.

### `messageType`
Type: URI

Identifies which message type this is. Form: `urn:ipproto:message:assetBootstrap`, `urn:ipproto:message:goalDecomposition`, etc. The full list is in the [vault index](../README.md).

### `protocolVersion`
Type: string

The protocol version this message conforms to. `0.4` for this version of the spec. A `0.3` message remains valid under 0.4, which adds optional fields only; a 0.3 receiver may ignore them. A `0.2` message remains valid under 0.3. A `0.1` message remains valid under 0.2, which only adds. A `0.1` receiver is expected to treat the 0.2 additions as unknown; a receiver that validates strictly against the 0.1 schemas does not do that and rejects some of them (see [VERSIONING](../../VERSIONING.md)).

### `originatingActor`
Type: [Actor Reference](Actor%20Reference.md) URI

Who produced the message.

### `originatingRoleDeclaration`
Type: [Actor Role Declaration](Actor%20Role%20Declaration.md) URI

The role under which the actor produced the message. The role declaration carries the contextual scope — workstream, milestone, subscription — under which the originator is acting.

### `addressedTo`
Type: array of structured entries

Each entry contains:
- `actorUri` — [Actor Reference](Actor%20Reference.md) URI of the recipient
- `expectedRole` — optional URI describing the role the recipient is expected to play

For broadcast messages (e.g., [Register Event](../03%20-%20Messages/Steady-State%20Events/Register%20Event.md) to all subscribers), the array can contain subscription URIs rather than specific actor URIs.

### `producedAt`
Type: ISO 8601 datetime

When the originating actor produced the message.

## Optional fields

### `userContext`
Type: [User Context](User%20Context.md)

The user at the originating actor who produced the message. Strongly recommended for messages that bind the actor to material decisions or costs (authorizations, commitments, payments).

Where another actor entered the message (see `recordedBy`), `userContext` still names a user of the originating actor, the person who gave the instruction or the answer, or is left out. The user of the recording actor goes into `recordedBy.userContext`, never here.

### `recordedBy`
Type: structured, optional. Added in 0.5.

The actor that entered this message on the originating actor's behalf. Sub-fields:
- `actorUri` — [Actor Reference](Actor%20Reference.md) URI of the recording actor, required
- `userContext` — [User Context](User%20Context.md) of the person at the recording actor who entered it, optional and strongly recommended

**When it is used.** An actor records a message for another when the originator acts outside the protocol: a supplier phones or e-mails its acceptance of an instruction, sends its deliverable or its invoice by mail, and the orchestrator's staff enter it. The message is the originator's: `originatingActor` and `originatingRoleDeclaration` name the originator and the role under which it acts, and the message binds the originator as if it had sent it. `recordedBy` says who typed it in. Before 0.5 the protocol had no way to say this; an implementation either named the recording actor as originator, which misstates who decided, or put the recording actor's staff into `userContext`, which misstates whose user they are.

**Consent.** The recording actor records only with the originator's consent: an agreement between the two, or the originator's instruction for the one message. The consent itself is outside the message. `recordedBy.actorUri` is never the `originatingActor` itself; a message an actor produces itself carries no `recordedBy`.

**On receipt.** A receiver treats the message as the originator's. It may apply its own policy to recorded messages, for example ask the originator to confirm a recorded acceptance of material value. An originator that did not consent says so to the recording actor; the protocol has no separate message for that, as for any other disagreement between two actors over a message they exchanged.

The field is optional. A receiver that does not know it ignores it, as for any unknown field, and reads the message as the originator's, which is right.

### `correlation`
Type: structured

Sub-fields:
- `correlatedToMessageUri` — references a prior message this one is in response to or builds on
- `workstreamUri` — the [Workstream](Workstream.md) this message belongs to, when applicable
- `milestoneUri` — the [Milestone](Milestone.md) this message belongs to, when applicable
- `subscriptionUri` — the [subscription](../03%20-%20Messages/Subscriptions/Service%20Subscription%20Started.md) this message belongs to, when applicable
- `eventChainUri` — when the message is part of a chain of events with a defined order

### `assertions`
Type: array of [Data Assertion](Data%20Assertion.md) structures

The data assertions this message is making against relevant records. Most messages carry assertions; pure status pings or event acknowledgments may not. Status transitions, evidence claims, deliverable productions, and similar all flow through this array uniformly.

## Required payload field

### `payload`
Type: structured, message-type-specific

The message-type-specific content. Each message specification defines the shape of its payload.

## Worked example skeleton

```json
{
  "messageUri": "urn:ipproto:message:c2e8f1a3-...",
  "messageType": "urn:ipproto:message:assetMatchInquiry",
  "protocolVersion": "0.4",
  "originatingActor": "urn:ipproto:actor:meridian-ip-group",
  "originatingRoleDeclaration": "urn:ipproto:roleDeclaration:orchestrator-001",
  "addressedTo": [
    {
      "actorUri": "urn:ipproto:actor:northwind-industries",
      "expectedRole": "urn:ipproto:role:assetOwner"
    }
  ],
  "producedAt": "2026-04-28T07:30:00Z",
  "userContext": { /* optional UserContext */ },
  "recordedBy": { /* optional, added in 0.5: the actor that entered the message on the originator's behalf */ },
  "correlation": {
    "correlatedToMessageUri": "urn:ipproto:message:a8e2c91a-..."
  },
  "payload": { /* message-type-specific */ },
  "assertions": [ /* DataAssertions */ ]
}
```
